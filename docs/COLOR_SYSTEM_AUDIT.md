# Карта цветовой системы всей CRM

**Дата:** 30.09.2026
**Область:** все пользовательские экраны CRM Detroid: вход, оболочка,
навигация, канбан, списки, карточки, формы, заявки, чаттер и админка.

Этот документ фиксирует собственные роли цвета перед изменениями. Это не
копия CSS, разметки или JavaScript Odoo. Публичные manifest и assets образца
прочитаны только текстово как ориентир: глубокая slate-основа тёмной темы,
несколько уровней поверхности, спокойная граница, бирюзовое действие и
приглушённый фиолетовый primary.

## 1. Что есть сейчас

Тема уже построена на переменных `--odoo-*` в `frontend/src/index.css` и
Tailwind-утилитах `bg-odoo-*`, `text-odoo-*`, `border-odoo-*`. Наиболее часто
используются роли фона, поверхности, границы, основного и приглушённого текста.
Это позволит изменить большую часть экранов без затрагивания API и поведения.

Аудит выявил две группы работ:

1. **Общие токены** — `bg`, `surface`, `surface-hover`, `surface-sunken`,
   `column-head`, `border`, `border-light`, роли текста, primary, action,
   success/warning/danger и контекстные акценты.
2. **Локальные исключения** — жёсткие HEX на экране входа, аватаре навигации,
   карте цветов этапов и отдельных inset-тенях заголовков таблиц. Их нужно
   заменить собственными семантическими токенами, чтобы светлая и тёмная темы
   не расходились.

## 2. Собственная целевая палитра

Значения ниже — палитра Detroid, подобранная по ролям на скриншоте владельца и
контрасту текста. Она не переносит сторонние классы или правила.

| Роль | Светлая тема | Тёмная тема | Назначение |
|---|---:|---:|---|
| Фон приложения | `#F7F6F8` | `#1B1D26` | свободная область, списки и подложка |
| Основная поверхность | `#FFFFFF` | `#262A36` | панели, карточки, поля, диалоги |
| Утопленная поверхность | `#F0EEF1` | `#20232C` | области группировки, таблицы, поля без фокуса |
| Hover-поверхность | `#F8F3F7` | `#303442` | строки, меню и кнопки без заливки |
| Обычная граница | `#DDD9DF` | `#3C3E4B` | панели, поля, таблицы |
| Мягкая граница | `#ECE9ED` | `#343744` | разделители и второстепенные линии |
| Основной текст | `#29252A` | `#E4E4E6` | заголовки и содержимое |
| Вторичный текст | `#625B63` | `#C8C8CC` | подписи и значения меньшего приоритета |
| Приглушённый текст | `#7C747D` | `#9A9AA0` | метаданные, иконки и плейсхолдеры |
| Primary | `#6B3E66` | `#6B3E66` | заполненные основные действия |
| Hover primary | `#593452` | `#82517C` | hover заполненной кнопки |
| Бирюзовый акцент | `#008F84` | `#02C7B5` | выбранное состояние, ссылки и действие |
| Успех | `#23864A` | `#46B86A` | подтверждение и успешный статус |
| Предупреждение | `#A86A00` | `#FFC107` | требующее внимания состояние |
| Ошибка | `#B83A4B` | `#E85765` | ошибки и опасные действия |

Светлый бирюзовый текст намеренно темнее тёмного: на белой поверхности это
сохраняет читаемость. Теги этапов и данных остаются функциональными цветными
маркерами; их контраст будет проверен отдельно, без смешения с фоном темы.

## 4. Порядок изменений и защита от побочных эффектов

1. Сначала заменить общие токены и локальные жестко заданные цвета оболочки.
   Это создаёт базу для всех экранов без переписывания каждого JSX-элемента.
2. Затем доработать рабочие экраны и оставшиеся локальные исключения только
   там, где общих токенов недостаточно.
3. На каждом шаге проверять светлую и тёмную тему, focus/hover/disabled,
   контраст текста, пустые состояния, модальные окна и узкий экран.
4. Цвета не являются изменением функций: данные, запросы, роли, доступные
   действия, маршруты и серверная часть остаются прежними.

## 5. Нужные материалы от владельца

Текущий широкий тёмный скриншот достаточен для основы и карточки лида. Перед
финальной приёмкой могут понадобиться скриншоты светлой темы и узкого экрана,
если их нельзя получить после выкладки из живой CRM. Отдельно запрашивать их
нужно только при невозможности точно оценить конкретный блок.

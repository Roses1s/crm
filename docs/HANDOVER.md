## Текущая работа

**Шаг 3 (11.10.2026): автосохранение заявки закрыто тестами — до продолжения
рефакторинга формы.** По решению владельца приоритет изменён: сначала защита
известной зоны риска, потом дальнейший перенос полей.

- Новый файл `frontend/src/features/shipments/shipment-autosave.test.tsx` —
  9 проверок фактического поведения: успешное автосохранение через три секунды
  простоя (с телом запроса, тостом «Сохранено» и снятой пометкой «не сохранено»);
  простой без правок не вызывает запросов; после сохранения повторов нет;
  пауза отсчитывается от **последней** правки, а не от первой; ручное нажатие
  «Сохранить» до истечения таймера не даёт второго запроса; новую заявку
  автосохранение не создаёт (её создаёт только кнопка); после ошибки запрос
  не повторяется, а правка руками снова включает автосохранение; уход со
  страницы — диалог и «Сохранить и перейти» дают ровно один запрос; если
  автосохранение успело пройти в открытом диалоге, переход продолжается сам
  без второго запроса (это замысел проекта: «завершилось во время перехода —
  продолжаем один раз», тот же код есть в карточке лида).
- Механизм автосохранения в рамках шага **не менялся** — только тесты.
- Тесты поймали изъян в самой проверке: поддельный сервер отвечает мгновенно,
  React склеивает состояния «идёт сохранение» и «ошибка» в одну отрисовку,
  эффект перезапускается только на реальном (или замедленном) ответе. С
  мгновенным ответом тест «после ошибки повторов нет» проходил даже со
  **сломанной** защитой. Поэтому в новых тестах сервер отвечает с задержкой
  400 мс (`slowResponses`) — как настоящий. Проверено подстановкой четырёх
  поломок в код формы: все четыре теперь ловятся тестами.

### Открытые вопросы к владельцу (не исправлялись, ждут решения)

1. **Округление маржи во фронтенде и на сервере расходится.** Карточка заявки
   показывает маржу, посчитанную во float (`netAmount` → `formatMoney`), а
   колонка списка — серверное значение на Decimal с `ROUND_HALF_UP`. На
   значениях ровно на границе округления возможна разница в копейку. Решение
   не принято, код не менялся.
2. **Существующий тест автосохранения карточки лида — слепой.**
   `src/features/crm/lead-autosave.test.tsx`, проверка «после неудачного
   автосохранения запрос не повторяется бесконечно»: проверено мутацией —
   при убранной защите (`autoSaveBlocked.current = true` в `onError`) тест
   **проходит**. Причина та же: мгновенный ответ поддельного сервера. Лечится
   тем же приёмом с задержкой ответа (правка только теста лида), но это
   отдельный шаг — ждёт решения владельца.

## Чем проверять

```bash
cd backend && .venv/bin/ruff check . && .venv/bin/ruff format --check . \
  && .venv/bin/mypy app && .venv/bin/python -m pytest
cd ../frontend && npm run lint && npm run format:check && npx tsc -b \
  && npm test && npm run build
cd .. && python scripts/snapshot.py
```

`alembic check` отдельно и только с SQLite (иначе лезет в PostgreSQL и падает
на DNS):

```bash
cd backend && rm -f /tmp/checks.db \
  && DATABASE_URL=sqlite+aiosqlite:////tmp/checks.db .venv/bin/alembic upgrade head \
  && DATABASE_URL=sqlite+aiosqlite:////tmp/checks.db .venv/bin/alembic check
```

Конфиг nginx локально проверить нечем — перед деплоем:
`ssh crm "cd /opt/crm && docker compose exec nginx nginx -t"`.

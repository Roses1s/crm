## В работе: поле «Назначенный бухгалтер» в карточке лида

Владелец попросил добавить под тегами в карточке лида выпадающий список из
10 указанных им имён и подпись «Выбрать», если значение пустое. Владелец
подтвердил план: список фиксированный, поле только в полной карточке лида,
менять его могут те же сотрудники, которым разрешено редактировать лид.
Поле не меняет продавца/ответственного за лид.

### План

1. Добавить необязательное поле в `leads`, API-схемы и миграцию Alembic;
   существующие лиды останутся без выбора. Разрешать в API только указанный
   список имён либо пустое значение.
2. Добавить поле после тегов в полной форме лида, связать его с состоянием и
   автосохранением формы; «Выбрать» будет очищать выбор. Быструю форму, список
   лидов и канбан не менять.
3. Добавить backend- и frontend-тесты на варианты, сохранение и очистку.
4. Обновить `PROJECT.md`, `STATUS.md`, `SNAPSHOT.md`, очистить HANDOVER после
   завершения; прогнать проверки, сделать отдельные проверенные коммиты и
   отправить только в `origin/arena/6d4bde73-crm`.

### Ограничения

- На сервер ничего не выкатывать: это делает владелец вручную.
- В песочнице нет Docker/PostgreSQL; схему проверять доступным Alembic/SQLite
  и CI, фактический production-деплой не выполнять.
- Рабочая ветка: `arena/6d4bde73-crm`.

**Готово на текущем шаге:** nullable `accountant_name` добавлено в модель,
`LeadCreate`/`LeadUpdate`/`LeadRead`; API принимает только 10 согласованных имён
и `null`. Создана миграция `20261007_0900_lead_accountant.py`. Тесты
`backend/tests/test_leads.py` прошли (32 теста), Ruff прошёл; генерация SQL для
перехода `e3f4a5b6c7d8:head` показала ожидаемый nullable-столбец.

**Далее:** добавить поле после тегов в полной карточке и тесты автосохранения;
быструю форму, список и канбан не менять. Полные проверки, обновление
PROJECT/STATUS/SNAPSHOT и отправка в origin — после завершения UI. Каждый
проверенный этап фиксируется отдельным коммитом; production-деплой не выполнять.

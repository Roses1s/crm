  9 проверок фактического поведения: успешное автосохранение через три секунды
  простоя (с телом запроса, тостом «Сохранено» и снятой пометкой «не сохранено»);
  простой без правок не вызывает запросов; после сохранения повторов нет;
  пауза отсчитывается от **последней** правки, а не от первой; ручное нажатие
  «Сохранить» до истечения таймера не даёт второго запроса; новую заявку
  автосохранение не создаёт (её создаёт только кнопка); после ошибки запрос
  не повторяется, а правка руками снова включает автосохранение; уход со
  страницы — диалог и «Сохранить и перейти» дают ровно один запрос; если
  автосохранение успело пройти в открытом диалоге, переход продолжается сам
  без второго запроса (это замысел проекта: «завершилось во время перехода —
  продолжаем один раз», тот же код есть в карточке лида).
- Механизм автосохранения в рамках шага **не менялся** — только тесты.
- Тесты поймали изъян в самой проверке: поддельный сервер отвечает мгновенно,
  React склеивает состояния «идёт сохранение» и «ошибка» в одну отрисовку,
  эффект перезапускается только на реальном (или замедленном) ответе. С
  мгновенным ответом тест «после ошибки повторов нет» проходил даже со
  **сломанной** защитой. Поэтому в новых тестах сервер отвечает с задержкой
  400 мс (`slowResponses`) — как настоящий. Проверено подстановкой четырёх
  поломок в код формы: все четыре теперь ловятся тестами.

  && DATABASE_URL=sqlite+aiosqlite:////tmp/checks.db .venv/bin/alembic check

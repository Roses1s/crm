# Эстафета: что делается прямо сейчас

> Страховка на случай, если сессия оборвётся. Чат новому участнику недоступен —
> доступен только репозиторий, поэтому всё важное живёт здесь.

---

## Задача

30.09.2026 владелец расширил визуальную задачу: привести цвета **всей CRM** к
единой собственной палитре по тёмному образцу Odoo. В область входят вход,
оболочка приложения, навигация, канбан, списки, карточки, формы, заявки,
чаттер, админка, диалоги, выпадающие меню, загрузка и пустые состояния.
Поведение, маршруты, API, права и бизнес-логику не менять.

Публичные manifest/CSS/JS Odoo разрешены только для текстового анализа ролей
цвета. Не скачивать их в репозиторий, не подключать и не исполнять. Тёмная тема
ориентируется на образец; светлая остаётся светлой, но использует те же
семантические роли и достаточный контраст.

## План по шагам

- [x] Шаг 1 — составлена карта экранов, общих компонентов и текущих цветов;
  безопасно сопоставлена с образцом. Собственная палитра и затронутые файлы
  зафиксированы в [`COLOR_SYSTEM_AUDIT.md`](COLOR_SYSTEM_AUDIT.md).
- [x] Шаг 2 — новая основа токенов применена к общим поверхностям, тексту,
  границам, статусам и focus-состояниям; добавлены роли навигации. Верхняя
  панель и аватар сотрудника больше не содержат жёстко заданных цветов.
  Утилиты общих кнопок, полей, таблиц, меню и диалогов получают новую палитру
  через существующие семантические токены.
- [x] Шаг 3 — рабочие разделы используют тематические цвета: этапы канбана
  получили контрастную карту, теги статусов теперь адаптируются к теме,
  предупреждения — семантический тон, а затемнения диалогов и предпросмотра —
  собственный overlay-токен. Поля форм и элементы выбора этапа используют
  тематический focus/бордер; поведение канбана, форм, заявок и чаттера не
  менялось.
- [x] Шаг 4 — вход, админка, загрузка и пустые результаты используют общие
  роли палитры. Вход теперь учитывает выбранную тему, автозаполнение полей не
  нарушает контраст, у скелетонов есть отдельный тематический тон, disabled и
  focus-состояния единообразны. Добавлено только визуальное пустое состояние
  стартового экрана; API, права и прочее поведение не менялись.
- [ ] Шаг 5 — пройти обе темы, широкий и узкий экран; после выкладки получить
  визуальное подтверждение владельца, обновить `STATUS.md` и закрыть эстафету
  отдельным коммитом.

## Первые файлы для аудита

- `frontend/src/index.css` — общие токены light/dark;
- `frontend/src/shared/ui/` — базовые визуальные примитивы;
- `frontend/src/shared/layout/`, `frontend/src/features/` — оболочка и все
  пользовательские экраны;
- `docs/ODOO_REFERENCE_ANALYSIS.md` — только карта наблюдений, без чужого кода.

## Проверки

После каждого кодового шага:

```bash
cd frontend && npx tsc -b && npm test && npm run build
```

Каждый шаг — отдельный commit, push и ожидание GitHub Actions. Если для точного
сравнения не хватает скриншота конкретного блока, попросить его у владельца,
а не подбирать вид «на глаз».

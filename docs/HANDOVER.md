# Эстафета

## Задача и ограничения

Работа идёт только в ветке `arena/6d4bde73-crm`. Общаться по-русски и простыми
словами; каждый шаг фиксировать отдельным коммитом и ждать зелёного CI.
Production не выкатывать и данные не менять.

Номера заявок не перенумеровывать. Не добавлять уникальность, пока повторы не
проверены на копии. Перед schema/data-изменениями нужна свежая резервная копия;
схему менять только отдельной Alembic-миграцией.

## Что остаётся

Фактические повторы номеров на копии пока не проверены: в рабочей песочнице нет
дампа, Docker и PostgreSQL. Поэтому шаг 9 **не завершён**. Номера не менялись,
ограничение уникальности не добавлялось.

В клоне на сервере уже есть обновлённый `deploy/restore-test.sh`. Он берёт свежий
дамп, восстанавливает его в отдельную временную БД, показывает повторы и удаляет
временную БД после проверки. Запуск владельцем:

```bash
ssh crm "cd /opt/crm && ./deploy/restore-test.sh"
```

Важно: скрипт сначала удаляет временную БД `crm_restore_test`, если она уже есть.
Запускать только если там нет нужных данных. В рабочую БД скрипт не записывает.
Для завершения шага 9 достаточно прислать вывод раздела о повторяющихся номерах;
сам дамп присылать не обязательно.

## Ограничения среды

В песочнице недоступны Docker, PostgreSQL, Valkey и sudo; конфиг Nginx локально
проверить нельзя. Секреты не добавлять. Production не менять и не выкатывать.

Заявки → как лиды (в работе): страница «Заявки» получила список в стиле
скриншота, а карточка заявки переписана 1в1 по образцу карточки лида (Odoo-вид):
панель управления с крошками, статусбар из 4 этапов (Новая → Проверена и
подписана заявка → Машина загрузилась → Машина выгрузилась), лист с блоками
(маршрут, контакты, перевозчик, груз) и правый чаттер (примечания, история смены
этапа, правка/удаление записей, вложения, Ctrl+V). Этапы = статус заявки
(ShipmentStatus: new/checked/loaded/unloaded, миграция данных). Лента заявки
живёт в timeline_entries через новую колонку shipment_id; лента лида фильтрует
shipment_id IS NULL. Доску-канбан для заявок решили не делать. Состав полей в
блоках карточки будет меняться отдельной задачей.

Блоки полей карточки заявки переделаны «как в реальном Odoo» (Этапы A+B):
модель заявки получила ~28 новых колонок (миграция `c3d4e5f6a7b8`) — реквизиты
заказчика (адрес, контакт, кто подписывает), информация о погрузке и выгрузке
(города-теги, адрес, контакт+телефон, даты «с/по», время «с/по»), сведения о
перевозчике (перевозчик, контакт, ТС, номер ТС, галочка «прицеп» + номер, ФИО,
телефон и паспорт водителя, кто подписывает) и информация о грузе (тип, упаковка,
объём кузова, масса, грузоподъёмность, тип кузова, способ погрузки-теги). Города
и способ погрузки хранятся списком строк (JSON) и вводятся чипами
(`frontend/.../shipments/TokenField.tsx`). Свойство `route` теперь строится из
городов-тегов с откатом на старые одиночные поля. Внизу карточки — вкладки
«Прочая информация» (комментарий) и «Позиции заказа» (таблица товаров/НДС — это
отдельный будущий Этап C, пока заглушка). Шапка «Компания» = своя «АДК Транс»
(статично, без поля в БД); ИНН заказчика подтягивается из выбранного лида.

Проверки зелёные локально и в GitHub Actions: фронтенд — `npx tsc -b`,
Vitest (25 тестов), `npm run build`; бэкенд — `ruff`, `ruff format --check`,
`mypy` (strict), pytest (70 тестов), `alembic upgrade head` (миграция up/down
проверена).

### Как быстро поднять предпросмотр карточки (dev, SQLite, без Docker)

Скрипт засева демо-лида лежит вне репозитория (в `/tmp/seed_preview.py`),
пересоздать при необходимости. Бэкенд на SQLite (кеш падает на in-memory,
лимитер выключен), фронтенд — `npm run dev` (проксирует `/api` на бэкенд).
Вход демо-админом `admin@example.com` / `Preview123`, карточка — `/crm/leads/1`.

Для выкладки на сервер (клон уже на ветке `arena/01a0f1e0-crm`):

```bash
ssh crm /opt/crm/deploy.sh
```

Следующую задачу начинать только по отдельному запросу владельца и с новым
согласованным планом.

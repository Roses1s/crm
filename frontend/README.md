# Фронтенд CRM Detroid — визуальный макет (этап 2)

React 19 · Vite 6 · Tailwind CSS v4 · TypeScript 5.7

Это **макет-заглушка**: полная визуальная система и все страницы из
референсного проекта, но **без единого запроса к бэкенду**. Данные берутся
из статических массивов в `src/shared/mock/`.

## Запуск

```bash
npm install
npm run dev      # http://localhost:5173
npm run build    # сборка в dist/
npm run preview  # предпросмотр собранной версии
```

## Страницы и маршруты

| Маршрут | Экран |
|---|---|
| `/login` | Вход (форма, кнопка просто ведёт на `/`) |
| `/` | Лаунчер приложений |
| `/crm` | Канбан лидов + переключение в список |
| `/crm/leads/:id` | Карточка лида: статусбар этапов, форма, вкладка «Заявки», чаттер |
| `/shipments` | Список заявок |
| `/shipments/:id` | Карточка заявки |
| `/admin` | Дашборд с графиком воронки |
| `/admin/users` | Пользователи |
| `/admin/carriers` | Перевозчики |
| `/admin/security` | Бэкапы и попытки входа |
| `*` | Редирект на `/` |

Набор маршрутов совпадает с исходным `router.tsx` один в один —
ничего не добавлено и не убрано.

## Дизайн-система

Все токены живут в `src/index.css`:

- `@theme inline` объявляет имена утилит (`bg-odoo-surface`, `text-odoo-text-muted`, …);
- значения — CSS-переменные в `:root` (светлая тема) и `.dark` (тёмная), перенесены
  из исходника **без изменений**;
- тема переключается классом `.dark` на `<html>` (`@custom-variant dark`),
  скрипт `public/theme.js` применяет её до первой отрисовки;
- шрифт Inter, базовый размер 13px, заголовки h1–h4 и скроллбар — как в оригинале.

Отличия синтаксиса от исходника (Tailwind v3 → v4):

| v3 | v4 |
|---|---|
| `tailwind.config.ts` + `postcss.config.js` | `@theme` в CSS + плагин `@tailwindcss/vite` |
| `colors.odoo.* = rgb(var(--x) / <alpha-value>)` | `--color-odoo-*: rgb(var(--x))` в `@theme inline` |
| `darkMode: ["class"]` | `@custom-variant dark (&:where(.dark, .dark *))` |
| `shadow-sm`, `rounded` | `shadow-xs`, `rounded-[4px]` (переименования v4) |

## Структура

```
src/
├── app/                  каркас: router, providers, layout (AppShell, Navbar)
├── features/
│   ├── auth/             страница входа
│   ├── launcher/         экран приложений
│   ├── crm/              канбан, список, карточка лида
│   ├── shipments/        список и карточка заявки
│   └── admin/            дашборд, пользователи, перевозчики, безопасность
└── shared/
    ├── lib/              cn, theme, owner
    ├── mock/             ← ВСЕ данные экрана лежат здесь
    ├── types/            те же интерфейсы, что и у будущего API
    └── ui/               button, chatter, odoo-form, form-section, skeleton
```

## Что намеренно вырезано

- `axios`, `@tanstack/react-query`, api-клиент, `unwrapList`, обработка ошибок HTTP;
- `zustand`-стор авторизации, `ProtectedRoute`, проверка ролей (`admin` / `manager`);
- все мутации: сохранение лида и заявки, смена этапа, архивация, CRUD пользователей
  и перевозчиков, загрузка и удаление вложений, отправка примечаний;
- `@dnd-kit` и перетаскивание карточек — карточки расположены статично;
- валидация (контрольная сумма ИНН), состояния загрузки и ошибок, скелетоны в потоке
  (компоненты скелетонов сохранены в `shared/ui/skeleton.tsx` на будущее).

Осталось только состояние интерфейса: открытие меню и выпадашек, переключение
канбан/список, сворачивание колонок, вкладки, сортировка и выделение строк
в списке, тема. Ни один обработчик не ходит в сеть.

## Подключение реального API (этап 3–4)

Каждый экран импортирует данные из `@/shared/mock/*`. Чтобы включить бэкенд,
достаточно заменить эти импорты на хуки TanStack Query — разметку трогать
не придётся, типы в `shared/types` уже совпадают с контрактом API.

# Фронтенд CRM Detroid

React 19 · Vite 6 · Tailwind CSS v4 · TypeScript 5.7 · TanStack Query v5

Приложение работает с настоящим API: данные, формы и действия ходят
в FastAPI-бэкенд (`backend/`). Моков не осталось.

## Запуск

```bash
npm install
npm run dev      # http://localhost:5173 (запросы /api проксируются на :8000)
npm run build    # сборка в dist/
npm run preview  # предпросмотр собранной версии
```

Бэкенд должен быть запущен на `http://127.0.0.1:8000` — адрес меняется
переменной `VITE_API_TARGET`. В продакшене прокси не нужен: nginx отдаёт
и статику, и `/api/` с одного домена.

## Страницы и маршруты

| Маршрут | Экран |
|---|---|
| `/login` | Вход (форма, кнопка просто ведёт на `/`) |
| `/` | Лаунчер приложений |
| `/crm` | Канбан лидов + переключение в список |
| `/crm/leads/:id` | Карточка лида: статусбар этапов, форма, вкладка «Заявки», чаттер |
| `/shipments` | Список заявок |
| `/shipments/:id` | Карточка заявки |
| `/admin` | Дашборд с графиком воронки |
| `/admin/users` | Пользователи |
| `/admin/carriers` | Перевозчики |
| `/admin/security` | Бэкапы и попытки входа |
| `*` | Редирект на `/` |

Набор маршрутов совпадает с исходным `router.tsx` один в один —
ничего не добавлено и не убрано.

## Дизайн-система

Все токены живут в `src/index.css`:

- `@theme inline` объявляет имена утилит (`bg-odoo-surface`, `text-odoo-text-muted`, …);
- значения — CSS-переменные в `:root` (светлая тема) и `.dark` (тёмная), перенесены
  из исходника **без изменений**;
- тема переключается классом `.dark` на `<html>` (`@custom-variant dark`),
  скрипт `public/theme.js` применяет её до первой отрисовки;
- шрифт Inter, базовый размер 13px, заголовки h1–h4 и скроллбар — как в оригинале.

Отличия синтаксиса от исходника (Tailwind v3 → v4):

| v3 | v4 |
|---|---|
| `tailwind.config.ts` + `postcss.config.js` | `@theme` в CSS + плагин `@tailwindcss/vite` |
| `colors.odoo.* = rgb(var(--x) / <alpha-value>)` | `--color-odoo-*: rgb(var(--x))` в `@theme inline` |
| `darkMode: ["class"]` | `@custom-variant dark (&:where(.dark, .dark *))` |
| `shadow-sm`, `rounded` | `shadow-xs`, `rounded-[4px]` (переименования v4) |

## Работа с данными

Компоненты не знают про `fetch` и адреса — только про хуки из
`src/shared/api/hooks.ts`:

```tsx
const { data: leads = [] } = useLeads({ search, stage, archived });
const moveLead = useMoveLead();          // перетаскивание карточки
const save = useUpdateLead(id);          // сохранение карточки
```

- `client.ts` — обёртка над fetch: подставляет JWT, разбирает единый формат
  ошибок `{detail, code, request_id}`, при 401 чистит токены и уводит на `/login`;
- `auth.ts` — токены в localStorage + `useIsAuthenticated()`;
- `hooks.ts` — запросы и мутации, ключи кеша в одном объекте `keys`.

Что уже подключено к API: вход и выход, лаунчер, канбан (фильтры, поиск,
перетаскивание карточек между этапами, создание/переименование/удаление этапов,
быстрое создание лида), список лидов, карточка лида (сохранение полей, теги,
приоритет, смена этапа, примечания, архивация), заявки (создание, правка, смена
статуса, фильтр по статусу), перевозчики, пользователи (CRUD), дашборд,
безопасность (бэкапы и журнал попыток входа).

Пока не подключено: загрузка и удаление вложений в чаттере — в API ещё нет
ручек для файлов.

## Мелочи, о которых стоит знать

- Фильтры канбана живут в адресной строке (`?stage=3&priority=2&view=list`) —
  ссылкой на отфильтрованную доску можно поделиться.
- Поиск отправляется на сервер с задержкой 300 мс.
- Перетаскивание карточки применяется оптимистично: карточка переезжает сразу,
  при ошибке возвращается на место и показывается предупреждение.
- Форма карточки лида отслеживает несохранённые правки: появляются иконки
  «сохранить / отменить», а браузер предупреждает при уходе со страницы.
